Reference sheet · Module 4 (Lessons 28 to 32)

Encoding and evolution: a migration review

Check three things separately: decoding, preservation through intermediaries, and application meaning. Then include time: mixed releases, retained history and rollback.

Boundary contract (Lesson 28)

  • Identifiers: agree on representation and range. Ordinary JS JSON.parse rounds numeric 9007199254740993 to 9007199254740992. Validate digit strings when exact text identity is the contract.
  • Money: specify units, currency, range, arithmetic and sign. A decimal-looking token does not guarantee exact decimal arithmetic.
  • Presence: document absent, null and default separately. Reject ambiguous duplicate keys when the contract requires it.
  • Text and bytes: distinguish code points, UTF-16 units and UTF-8 bytes. Padded Base64 length = 4 × ceil(bytes/3), before surrounding syntax.
  • XML: schema datatypes exist; check that the actual reader validates and preserves them. CSV: quoted fields can contain commas and newlines; use the correct dialect parser and typed import rules.

  • Reserve deleted Protobuf field numbers and names. A binary-safe rename can still affect JSON mappings.
  • An Avro reader default fills a field missing from the writer schema. It is not retroactively stored in old records.
  • Schema retention and distribution belong to recovery and replay design. A small payload is useless without the knowledge needed to interpret it.

Verified bare sample {"id":150,"name":"Zoë"}: compact JSON UTF-8 24 bytes; explicit-presence Protobuf 9; Avro 7. Not equivalent integer domains or a total-system benchmark; schema distribution, framing, compression and CPU are excluded.

Write the arrows (Lesson 30)

CompatibilityRequired pair
Backwardold writer → new reader
Forwardnew writer → old reader
FullBoth directions for the checked versions
  • Test mixed-version cells, not only each release against itself.
  • For our Avro subset: int→long is backward only; adding currency without a default is forward only; adding with a valid reader default works both ways.
  • Separate reader preparation from writer activation. The deployment order must follow the actual matrix; forward-only live compatibility does not solve retained old data.
  • Code rollback leaves newly written bytes behind. Verify the rollback reader, or use a compatible prepared rollback release.
  • Retire old support only when live, replay, backup, queued-work and rollback obligations end.

Follow every rewriting hop (Lesson 31)

  • List serializer, deserializer, encoding, schema source and deployed versions at each hop.
  • Classify an intermediary: read only, opaque forwarding, or decode/rewrite. Test new → old updater → new for the last kind.
  • Normal Protobuf binary editing preserves our unknown currency field. Known-field reconstruction and an old-message JSON round trip lose it. ProtoJSON may reject unfamiliar fields by default.
  • A database read-modify-write path can erase new fields. Reading successfully is not a preservation guarantee.
  • Request arrow: client writer → server reader. Response arrow: server writer → client reader. Method support and timeout/retry semantics remain separate.
  • Kafka replay and archives can contain much older producer versions. Registry framing and policies depend on the actual serializer ecosystem, not just the broker name.

Three-version traps (Lesson 32)

Removed-default bridge: v1 has no currency; v2 adds currency with USD default; v3 removes the default. Reader v2 reads v1, reader v3 reads v2, but reader v3 cannot read v1. Adjacent checks miss this. Check all required historical writers; verify registry transitive policy and scope.

Units trap: v1 writes 1,200 cents; v3 writes 12 dollars under the same integer field. All cells decode. Old→new reads 120,000 cents; new→old reads 12 cents. Assert the intended USD 12.00 separately from decode success.

  1. State the application invariant.
  2. List retained writer versions.
  3. List live mixed-version pairs.
  4. Name the rollback reader.
  5. Execute required pairs and assert interpreted values and preservation.
  6. State evidence permitting retirement of old handling.

Evidence and limits

Independent fixtures: 70 wire examples, 54 Avro pairs, four Protobuf intermediary paths, reused-tag behavior and text-parser cases. Reproduce them with Avro 1.12.0 and Protobuf 6.33.5. Browser codecs are a flat-record subset, not production libraries or registry validators. The unit exercise checks declared sample amounts; no fleet, broker, database protocol, network guarantee or latency was measured.
