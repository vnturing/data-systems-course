Measuring systems: formulas and rules

The arithmetic and habits from Lessons 6 to 11 on one page. Print-friendly.

Vocabulary (Lesson 6)

TermMeaning
FaultAdjudged or hypothesized cause of an error (a bug, a bad config, a failed disk, a dependency's failure seen from your side)
ErrorPart of system state that may lead to a service failure; may be latent or detected; many never become failures
FailureDelivered service deviates from correct service (what the user sees)
Fault toleranceError detection + recovery so faults do not become failures

Redundancy (independent failures, each replica down with probability p): 2 replicas either may serve: p². 3 replicas any one may serve: p³. 2-of-3 majority: 3p² − 2p³. Any common-mode fault probability c is a floor: unavailability ≥ c. Ask which replicas share a zone, deploy, codebase, credential or dependency.

Latency (Lesson 7)

  • Report p50, p99, p99.9. Never the mean alone. Never average percentiles; store histograms or sketches and merge them.
  • Fan-out of N calls, each slow with probability q: P(request slow) = 1 − (1 − q)N. (q = 1%, N = 100: 63%.)
  • Hedged request: send a second copy after the single-call p95; extra load about 5%. Fixes the common slow call, not correlated slowness or double-slow events. Hedges are retries: idempotency applies.
  • Load tests: open model (constant arrival rate), latency measured from the scheduled send time. A closed loop omits exactly the slow samples (coordinated omission).

Load and fan-out (Lesson 8)

  • Write down: writes/s, reads/s, fan-out (average and maximum), delivery deadline.
  • Per follower per day: push = tweets × insert cost; pull = reads × merge cost. Follower count cancels. Pull wins in total work when reads × merge cost < tweets × insert cost.
  • Hybrid threshold = largest account whose single write can finish in the deadline: followers ÷ fan-out throughput ≤ deadline.

  • M/M/1: mean response = s / (1 − ρ); p99 ≈ 4.6 × mean. Queueing wait scales with (1 + SCV) / 2 (Pollaczek–Khinchine): reduce variance (separate queues by size, break up big work) as well as load.
  • Little's law: L = λ × W. 500 req/s at 40 ms means about 20 in flight; if the dependency is 4× slower, you need 4× the concurrency.
  • Backlog drain time = backlog / (μ − λ). If λ ≥ μ, it never drains.

  • SLI = measurement; SLO = internal target; SLA = contract with consequences (usually looser than the SLO).
  • Error budget = 1 − SLO. Burn rate = observed error rate ÷ allowed error rate. 100% errors vs 99.9% = 1,000× (budget gone in 43 min). 5% errors = 50× (14.4 h).
  • Serial hard dependencies multiply: five at 99.9% = 99.5%. Make some optional or redundant; assume independence only after checking.
  • Latency SLI as a threshold count: “99% of requests under 300 ms” = p99 ≤ 300 ms.

Operability and admission control (Lesson 11)

  • Acid test: can operators take down any server at any time without draining it first?
  • Under overload, FIFO + impatient clients = the server works on requests nobody is waiting for; goodput collapses and the collapse outlasts the surge.
  • Defenses: bounded queues, request deadlines (drop the expired), concurrency limits, shedding at the edge; clients limit retries with budgets (Lesson 5).
  • Check what each component does at 2× load before it happens.
