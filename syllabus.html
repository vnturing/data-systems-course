Syllabus

The full map

Thirteen modules, about 85 lessons, three capstone design reviews. Each lesson is short (20 to 40 minutes), ends with a retrieval check, and names something you can do at work. ✓ built lessons are live; ○ planned ones are scoped here and get built in order.

Order matters: Part I is a single machine, Part II is what breaks when data spans machines, Part III is how to compose systems out of the pieces.

Part 0 · Orientation

Module 0 · The distributed mindset

  1. The timeout problem built — make retries safe with idempotency keys
  2. What if it dies right here? built — review any MySQL + Kafka handler with the crash-point drill; fix it with an outbox
  3. System models: say your assumptions out loud built — write the model line; tune a failure detector knowingly
  4. Safety and liveness: what "correct" means built — set Kafka durability knobs as a deliberate trade-off
  5. Retries done right: timeouts, backoff, jitter, budgets built — configure retries on AWS without amplifying outages

Part I · Foundations on one machine

Module 1 · Measuring systems: reliability, scalability, maintainability

  1. Faults, errors, failures, and what redundancy can and cannot do built — describe incidents as chains; see why replicas in one fault domain stop helping
  2. Percentiles, the tail, and how to measure latency honestly built — fan-out arithmetic, hedged requests, never average percentiles, coordinated omission
  3. Fan-out on write or on read: describing load built — why the delivery deadline, not total cost, forces the hybrid
  4. Queueing and the cliff built — 1/(1-utilization), variance, Little's law, why lag never drains
  5. SLIs, SLOs and error budgets built — budgets, burn rate, dependency ceilings
  6. Operability and admission control built — refuse work early or collapse late (evolvability moves to Module 4)
