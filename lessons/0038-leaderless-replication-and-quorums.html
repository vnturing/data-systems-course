Leaderless replication: what a quorum proves

R + W > N is a statement about overlapping sets. It becomes a freshness argument only after you name what those sets contain and how versions are interpreted.

~35 min1 interactive4-question check
What you can do after this lessonProve or refute read/write intersection for fixed membership, then list the durability, version-ordering and concurrency assumptions the arithmetic does not prove.

1. A coordinator need not be a leader

In a leaderless design, a coordinator can send a key’s write to several replicas and wait for a chosen number of replies. A read can collect several responses and reconcile versions. “No leader” does not mean no coordinating request process, no membership rule or no conflict policy.

Let N be the fixed home replica count, W the required write acknowledgements, and R the required read responses. Suppose a completed write is durable on its W responders, no later write intervenes, all sets use the same membership, and a read can correctly identify that version.

2. The pigeonhole argument

Disjoint sets of sizes W and R would contain W+R different members. If W+R>N, they cannot both fit inside the same N-member universe. Therefore every such read set intersects every such completed write set. With N=3, W=2 and R=2, the minimum intersection has one member.

Gifford’s weighted-voting work makes intersection part of a fuller protocol with versioning and transactional assumptions.[1] Borrowing its arithmetic does not automatically import the whole protocol or its guarantees.

Try: enumerate N=3, W=1, R=2 and find a disjoint witness. Increase W to 2. Then choose N=5 and vary the thresholds. The model enumerates all sets; its result is an exact finite combinatorial check, not a simulated network measurement.

3. What the intersection does not establish

  • A failed write: a timeout can leave data on fewer than W replicas. It may become visible even though no success response was returned.
  • Concurrency: overlapping write sets do not by themselves serialize writers. A replica might store competing versions or apply a timestamp policy that discards one.
  • Membership: substituting fallback nodes can make the actual read/write sets disjoint even when their counts satisfy the formula.
  • Durability: a response from volatile memory does not establish the same failure tolerance as a durable record.
  • Version choice: a maximum wall-clock stamp need not represent a causally later update.

For fixed membership, 2W>N additionally gives write/write intersection. Again, two writers contacting a common replica need a protocol at that replica to turn overlap into exclusive ordering. A plain replicated register with quorum counts is not automatically linearizable.

4. Repair works through evidence

Read repair can update stale contacted replicas when a read discovers a newer value. Anti-entropy compares replicas in the background, including keys that readers rarely touch. Hinted handoff retains a deferred delivery for an unavailable destination. These mechanisms have different triggers and failure/retention requirements.

Apache Cassandra documents its read-repair behavior and how blocking repair can protect monotonic quorum reads in a partial-write scenario.[2] Read repair still cannot discover an unseen value if every contacted replica has the same stale copy. Lesson 41 makes that counterexample executable.

5. Sloppy membership changes the theorem’s premise

Dynamo’s sloppy-quorum design permits temporary substitutes from a preference list when home nodes are unavailable.[3] If A and D store a write for a home set {A,B,C}, a later read from {B,C} can miss it. R=2, W=2 and N=3 describe counts, but {A,D} was not a subset of the assumed home universe.

Do not fix that reasoning by silently redefining N for each request. State the actual acknowledged holders, reader responders and handoff assumptions. Dynamo’s 2007 design and modern DynamoDB APIs are different contracts; neither this model nor the paper is a substitute for the service documentation you deploy.

Check yourself

Optional: apply the mechanism (20 minutes)

For a quorum claim in a design doc, write the actual membership universe, responders, durability boundary, version ordering and partial-write behavior. Exhibit a set intersection rather than quoting only a formula.

Ask the course agent about any unclear result. Include the topology, acknowledgement contract and exact failure or message sequence.
